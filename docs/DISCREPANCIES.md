# DISCREPANCIES — SPEC.md vs. official Binance docs

Verified on **2026-10-12** against developers.binance.com (USDⓈ-M Futures). Sources:

- `https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/*` (general-info,
  websocket-market-streams/{Connect, Important-WebSocket-Change-Notice, How-to-manage-a-local-order-book-correctly},
  user-data-streams, error-code, common-definition, change-log), fetched via the site's `llms.txt` markdown exports.
- Endpoint reference (paths, weights, parameters) from the official generated connector
  `binance/binance-connector-python` → `clients/derivatives_trading_usds_futures` (commit of 2026-10-09), whose
  docstrings link back to `developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/...`.
- Live checks against public endpoints (no keys): `GET /fapi/v1/exchangeInfo`, WebSocket samples on prod and demo.

Rule (SPEC §0.3): **the docs win.** The code follows the docs. Each item says what the code does.

| 22 | **Book sync bridging event** | follow the official procedure | Doc step: first processed event must satisfy `U ≤ lastUpdateId ≤ u`. Observed/derived: when the REST snapshot is taken exactly at the previous event's final id (quiet market, `lastUpdateId == u_prev`), the next event has `U > lastUpdateId` and the strict rule would loop on resyncs forever. Also observed live: the REST snapshot is sometimes *older* than the first buffered event (needs a refetch). | First event accepted if `U ≤ lastUpdateId ≤ u` **or** `pu == lastUpdateId` (same continuity rule as step 6). Old snapshots are refetched (counted as `stale_snapshots`, not as gaps). |
