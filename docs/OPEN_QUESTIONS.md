# OPEN QUESTIONS — decisions taken (most conservative option)

Rule (operator instruction + SPEC §0.7): every open question gets the **most conservative** option, recorded
here. The operator can change any of these via `config/config.yaml`; none is changed programmatically.

## A. SPEC §13 — questions for the operator

| # | Question | Decision | Why it is the conservative choice | Where |
|---|---|---|---|---|
| A1 | Quote size and inventory limits after M5 — scale factor and cadence? | **No automatic scaling, ever.** Sizes/limits stay at the start values until the operator edits config. Suggested manual policy (RUNBOOK): at most ×1.5 per step, at most one step per 14 days, only if the symbol has ≥ 500 live fills with realized edge > 0 at 1σ, zero HALTs and zero unresolved RECON_MISMATCH in the period. | SPEC §11.5 forbids programmatic limit increases; slow manual steps bound the damage of an edge estimate that is wrong. | config only; RUNBOOK §6 |
| A2 | Taker hedging, or post-only only? | **Post-only only** (`hedge.allow_taker: false`). Hedges are GTX near the touch; if exposure grows the risk engine's `max_net_beta_exposure_usdt` moves the account to REDUCE_ONLY. | An automated taker order is the fastest way for a bug (e.g. bad beta) to lose money; the risk engine already bounds beta exposure. | `hedge/hedger.py` |
| A3 | Funding guard: widen vs pull? | **Pull** (`quoting.funding_guard_action: pull`), ±60 s around each funding timestamp. Deviates from the SPEC sample config (`widen`). | No quotes → no fills around the funding print, when spreads/flow are least predictable. | `quoting/engine.py` |
| A4 | Telegram vs other alert channel? | **Telegram (as specified) plus a local append-only `logs/alerts.log` that always receives every alert.** If Telegram is not configured or fails, alerts are still written locally and in the JSON log. | Keeps the specified channel, removes the single point of failure. | `ops/alerts.py` |
| A5 | Hosting: home server vs VPS? | **VPS** with a static IP (for the API-key IP whitelist), in AWS Tokyo (ap-northeast-1) or a provider close to it, running `docker compose` with `restart: unless-stopped`. HALT is persisted so an automatic restart can never resume trading. | Stability (power/network) and a fixed IP matter more than latency for us. | `docker/`, RUNBOOK |

## B. Design decisions not covered by SPEC

| # | Topic | Decision (conservative) | Where |
|---|---|---|---|
| B1 | Milestone gating | SPEC §0.1 applies: stop after each milestone and wait for operator approval. The M0–M4 code was built in one pass before any wall-clock acceptance run; as of 2026-10-12 the operator has confirmed that **M5 does not start** until the M1 (24 h), M3 (7-day shadow) and M4 (72 h demo) acceptance runs pass and are approved. Plan: `docs/ACCEPTANCE_PLAN.md`; status: `docs/PROGRESS.md`. **Update 2026-10-12:** the operator asked for M5–M7 to be built; read as approval to **write and unit-test** the code only, not to run live. Live stays hard-blocked by `LIVE_ACCEPTANCE_APPROVED = False` until the operator separately confirms the acceptance runs passed; the `MODE=live` + `LIVE_CONFIRM` gate and the startup checks are unchanged. | `orders/live_venue.py` |
| B2 | σ in the quoting formulas | SPEC writes `σ_bps` (reservation) and `σ_bps_per_horizon` (half-spread). Both use `σ_h = σ_1s · sqrt(quoting.sigma_horizon_s)`, default horizon **5 s** (= the toxicity markout horizon). `vol_kill_bps` is compared with the exposed σ (bps/√s, per SPEC §5.3). | `quoting/engine.py` |
| B3 | Requote | **Cancel → wait for confirmation → place new.** Never two live orders on the same side/level; a PENDING_CANCEL order still counts toward exposure. Modify-order (`PUT /fapi/v1/order`) not used in v1. | `orders/manager.py` |
| B4 | REDUCE_ONLY quoting | In REDUCE_ONLY only the inventory-reducing side is quoted, with `reduceOnly=true` and qty ≤ |position|; everything else is pulled. In HALTED nothing is quoted (flatten logic only). | `quoting/engine.py`, `risk/engine.py` |
| B5 | Which breaches are soft vs hard | Soft → REDUCE_ONLY: position/gross/net-beta/leverage over limit, liquidation distance < min, daily loss ≥ 75 % of limit. Hard → HALTED: daily loss limit, max drawdown, kill switch, unhandled exception in order/risk path, HTTP 429/418, user-stream down > 60 s with open exposure, recon mismatch that cannot be resolved. REDUCE_ONLY → OK only when every metric is back below `resume_frac` (90 %) of its limit. | `risk/engine.py` |
| B6 | HALT persistence | HALTED is written to `state/riverbank.sqlite`; the bot refuses to start while a HALT record exists or `./KILL` exists. Operator clears it with `tools/clear_halt.py` after investigating. | `risk/killswitch.py`, `tools/clear_halt.py` |
| B7 | 429 / 418 | Treated as hard breach → HALTED; no request is sent until `Retry-After` (min 60 s) elapses; the exchange-side dead-man (countdownCancelAll) cancels resting orders if heartbeats cannot be sent. | `exchange/rate_limiter.py` |
| B8 | Paper fill model extras | In addition to SPEC §5.8: (a) if the visible book crosses our resting order (best ask ≤ our bid) we are filled at our price — adverse fills must not be skipped; (b) queue is decremented with `aggTrade.nq` (non-RPI qty); (c) a post-only order that would cross at arrival time is rejected; (d) no cap of queue-ahead by visible size (literal SPEC: unexplained decreases never advance us). | `sim/paper_fills.py` |
| B9 | Realized edge definition | SPEC §1 `edge = half-spread + markout − fee` while §5.9 measures markout against the **fill price** (which already contains the half-spread). Implemented: `markout_bps(h)` per §5.9; `realized_edge_bps(h) = markout_bps(h) − fee_bps` (= half-spread + mid move − fee, no double counting). | `analytics/markout.py` |
| B10 | Promotion criterion | Promote only if `n ≥ min_fills_for_promotion` **and** `mean − 1·SE > 0` of realized edge at `universe.promotion_horizon_s` = **60 s**. Demote if over the last `demotion_window_fills` live fills `mean + 1·SE < 0`. Never decide on fewer fills. | `universe/rotation.py` |
| B11 | Auto-promotion | `universe.auto_promote: false` by default: shadow evidence makes a symbol *eligible*, the operator lists it in `universe.live_symbols`. Auto-demotion is always on (it only reduces risk). | `universe/rotation.py` |
| B12 | Shadow mode and fees | Shadow never calls signed endpoints on production, so `commissionRate` is not read; config fees are used. | `main.py` |
| B13 | Symbols allowed | Besides SPEC hard exclusions: `underlyingType == COIN`, ASCII-only symbol, `positionControlSide == NONE`, client-id length ≤ 36. | `universe/screener.py` |
| B14 | Order size rounding | Quantity is rounded **down** to step; a symbol where the rounded size cannot meet `min_qty`/`min_notional`, or where one order exceeds `max_position_usdt`, is ineligible. Effective inventory units = `min(max_inventory_units, floor(max_position_usdt / order_notional))`. | `quoting/sizing.py` |
| B15 | Book validation method (M1) | L1–L5 are compared between the long-running book and a *fresh* book built from a new REST snapshot plus the same buffered diffs, **at the same final update id** (exact comparison). A direct REST-vs-stream comparison is not exact because snapshots fall inside 100 ms diff batches. | `tools/validate_book.py` |
| B16 | Staleness | A symbol is STALE when neither depth nor bookTicker updated for `stale_ms`, even if the connection is alive (illiquid symbol) → quotes pulled. | `marketdata/gateway.py` |
| B17 | Reconnect safety | On an unexpected market-data disconnect the affected books are marked INVALID (quotes pulled) and resync from a new snapshot; planned 24 h rolls are make-before-break and duplicates are dropped by update id, so continuity is still verified with `pu`. On user-stream disconnect all quotes are cancelled via REST and quoting resumes only after a successful REST reconciliation. | `orders/manager.py` |
| B18 | Requote churn / exchange quantitative rules | `requote_ticks: 1` (SPEC default) on symbols whose tick ≈ 1 bps makes the reservation cross a tick every few hundred ms. Binance enforces *Futures Trading Quantitative Rules* (`GET /fapi/v1/apiTradingStatus`, e.g. unfilled-ratio indicators) that can lock an account for excessive cancels. Decision: requotes **away** from the touch (protective) are immediate; requotes **toward** the touch wait until the order is `quoting.min_requote_interval_ms` (1000 ms) old. Measured on synthetic replay: order count halved (10.9k → 5.7k per 25 min, 2 symbols). Demo/live poll `apiTradingStatus` and pause a symbol whose indicator approaches its trigger. Operator may raise `requote_ticks`. | `orders/manager.py`, `orders/live_venue.py` |
| B19 | Liquidation distance vs leverage | With the SPEC sample (`leverage: 3`, isolated) a fresh **short** sits only ≈30.1 % (long ≈31.6 %) from its liquidation price, so `min_liq_distance_pct: 30` is breached by almost any adverse tick → the venue lives in REDUCE_ONLY (observed in the first live shadow smoke run: REDUCE_ONLY after 70 s). Decision: **per-symbol leverage setting = 2** (`account.leverage: 2`, liquidation ≈46–49 % away) — strictly less leverage, i.e. more conservative; the risk limit `max_leverage: 3` (gross/equity) is unchanged. Paper venues use an isolated-margin approximation (mmr 2.5 %); real venues use the exchange's `liquidationPrice`. REDUCE_ONLY resumes only when every metric is below 90 % of its limit. | `core/config.py`, `config/config.yaml`, `risk/limits.py` |
| B20 | Order size stability | Order size is computed from a reference price and only recomputed after a > 5 % price move, so a price oscillating around a step boundary does not cause size-change requotes. | `engine.py` |
| B21 | Live symbol selection (M5) | ACTIVE = symbols in the current screened universe that pass B10 on **shadow evidence** and are in `universe.live_symbols` (unless `auto_promote`), not in demotion cooldown, best edge lower bound first, capped at `max_active_symbols`. Empty allow-list → live quotes nothing. Evidence comes from the shadow service's DB (`universe.shadow_db`), opened **read-only**; live refuses to start if that file is missing or is its own DB (live needs its own `ops.state_dir`, see `config/live.yaml`). Every selection is written to `universe_decisions`. On macOS Docker Desktop do not read the shadow DB across the VM boundary (RUNBOOK §3.2). | `universe/rotation.py` |
| B22 | Shadow-vs-live gap source (M5) | Demo and live run a **shadow twin** (paper venue `shadow`) on the real venue's symbols in the same process and DB; gap = real − twin for fill rate per quoted hour, markout 5 s and realized edge (SE combined). The twin's HALT is not persisted and does not affect the real venue (a simulated venue must never block a real restart); `halt_all` (kill switch, engine exception) still halts both. | `orders/live_venue.py`, `analytics/gap.py` |
| B23 | Beta and hedger details (M6) | **Beta:** OLS on 1-min log returns from public REST klines (completed candles only), window `hedge.beta_window_days` (3 d), shrunk toward 1.0 by `beta_shrink`, refreshed every `beta_refresh_s`; fewer than 360 overlapping returns (6 h) or a failed refresh → prior 1.0 / previous value. Betas are estimated vs every hedge instrument and used by the risk engine's net-beta metric even when `hedge.enabled: false` (SPEC §5.6/§5.7 define net beta with β_i). **Hedger:** acts only when the venue risk state is OK (REDUCE_ONLY/HALTED → hedge orders pulled; HALTED flattening closes hedge positions); trigger is |net beta vs the first instrument| > `hedge_threshold_usdt`; instrument = first in `hedge.instruments` whose floor(|exposure_H| / mid, step) meets min qty and min notional (with SPEC defaults BTCUSDT's 100 USDT min notional exceeds `max_position_usdt` 50, so ETHUSDT is used); size rounded **down** and capped so the instrument's position stays ≤ `max_position_usdt` (never over-hedge); one hedge order per venue at a time, GTX at our own side of the touch; a resting hedge is kept while side/price match and its remaining qty ≤ target, otherwise cancelled and replaced after the cancel confirms. Taker (IOC market) only if `allow_taker` and |exposure| > `hedge_urgent_usdt` (A2: off). | `hedge/beta.py`, `hedge/hedger.py` |
| B24 | Auto-rotation runtime (M7) | Live only (demo keeps its configured list: demo PnL is meaningless). Every `universe.screen_interval_s`: demote ACTIVE symbols per B10 (or → CANDIDATE when they leave the screened universe), release DEMOTED → CANDIDATE after the cooldown, then fill **free** slots by promotion (B21 rules). A better candidate never displaces a healthy ACTIVE symbol (no churn). A newly promoted symbol gets ISOLATED margin + leverage on the exchange **before** it is quoted; if that fails it is recorded ACTIVE → CANDIDATE and skipped. Removed symbols wind down (reduce-only until flat), on the real venue and its shadow twin. Every decision → `universe_decisions`, a `universe_decision` log line and an INFO alert. A failed rotation keeps the current set and alerts (the risk engine still bounds every symbol). Multi-level quoting: supported and tested on the real-venue path; configs keep `quoting.levels: 1` (SPEC: optional). | `universe/rotation.py`, `orders/live_venue.py` |
